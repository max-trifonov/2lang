## Контекст / зачем
Учатся несколько взрослых на одном телефоне, без регистрации (`D-10`: всё локально). У каждого свои языки, язык интерфейса (`D-4`), цель дня и — в следующих задачах — свой прогресс. Профиль — корень всех пользовательских данных, поэтому делается до уроков и загрузки текстов.

## Цель
Первый запуск просит создать профиль; дальше приложение открывается в последнем активном профиле, профиль можно переключить, добавить, изменить и удалить. Данные переживают перезапуск и офлайн.

## Объём
**Входит:**
- модель профиля: имя, цвет, язык интерфейса, изучаемые языки (EN/ES), цель дня; правила валидации;
- локальная БД приложения на IndexedDB (схема и миграции в одном месте) и хранилище профилей поверх неё;
- первый запуск → экран создания профиля; активный профиль запоминается;
- вкладка «Профиль»: карточка активного профиля, переключение на другой, «Добавить», «Изменить», «Удалить» (с подтверждением, кроме последнего профиля), тема;
- язык интерфейса — настройка профиля: переключение профиля меняет язык;
- «Главная» приветствует активный профиль и показывает цель дня;
- все строки — i18n RU/EN/ES.

**Не входит:**
- прогресс, уроки, FSRS — только договорённость, что любые данные ученика ключуются `profileId` и удаляются вместе с профилем;
- PIN/защита профиля, аватары-картинки, тема на профиль (тема остаётся общей для устройства);
- экспорт/импорт (отдельная строка BL-1), синхронизация (`D-10`, этап 2).

## Критерии приёмки (AC-1…N)
- **AC-1.** Первый запуск (профилей нет) открывает экран «Кто учится?»; без созданного профиля на вкладки не попасть.
- **AC-2.** Профиль создаётся с именем, языком интерфейса, изучаемыми языками (хотя бы один из EN/ES) и целью дня; пустое, слишком длинное или повторяющееся (без учёта регистра) имя не сохраняется — с понятной ошибкой у поля.
- **AC-3.** После перезапуска приложение открывается в последнем активном профиле и на его языке интерфейса.
- **AC-4.** Во вкладке «Профиль» можно переключиться на другой профиль одним касанием; язык интерфейса и приветствие на «Главной» меняются сразу.
- **AC-5.** Профиль можно изменить (те же правила, что при создании) и удалить после подтверждения; последний профиль удалить нельзя; при удалении активного активным становится другой.
- **AC-6.** Всё работает без сети.

## Решения
- **D-1. Хранилище — IndexedDB, своя тонкая обёртка без зависимостей.** Прогресс (тысячи карточек FSRS) пойдёт туда же; `Preferences` на вебе — это `localStorage` (лимит, синхронный, строка на ключ). Одна БД `twolang`, схема и миграции — в `src/db/`. В PWA запрашиваем `navigator.storage.persist()`, чтобы браузер не вычистил данные.
- **D-2. Цель дня — в уроках (1–5), по умолчанию 2.** Урок 5–7 минут (`D-7`), считать уроки проще и понятнее, чем минуты, и не требует таймера.
- **D-3. Язык интерфейса — поле профиля** (`D-4` «выбор в профиле»). Языковой чип в «Профиле» правит активный профиль; общая настройка языка устройства просто следует за активным профилем (нужна до загрузки БД — для экрана загрузки).
- **D-4. Старт — в последнем активном профиле**, без экрана выбора на каждом запуске: чаще телефоном пользуется один человек; переключение — во вкладке «Профиль».
- **D-5. Цвет профиля** — из палитры 8 цветов, первый свободный при создании; меняется в форме. Инициал + цвет различают профили без картинок.
- **D-6. Изучаемые языки — подмножество `en`/`es`**, по умолчанию оба; порядок фиксированный (EN ведущий, `D-1`).

## Подход
Домен `features/profiles/domain` (тип, `validateProfileDraft`, `pickColor`) → порт `ProfileRepository` → адаптер на IndexedDB (`src/db`) → Pinia-стор `useProfilesStore` (загрузка до `mount`, активация меняет язык) → роутер-guard «нет профиля → /welcome» → экраны: форма профиля (создание/правка), вкладка «Профиль», приветствие на «Главной».

## Тесты
Класс риска: **К2** — валидация черновика, выбор цвета, логика стора (активный при удалении, запрет удалить последний); **К1** — хранилище (данные ученика): integration на `fake-indexeddb` — сохранение/чтение/удаление, активный профиль, переживает переоткрытие БД. Экраны — К3, без тестов: ручной смоук по AC в браузере.

| Вход | Ожидание |
|---|---|
| имя «  », 25 символов, «анна» при существующей «Анна» | ошибки `name_empty` / `name_too_long` / `name_taken` |
| правка «Анна» → «Анна» (сам себя) | без ошибки |
| языки `[]`, цель 0 и 6 | ошибки `languages_empty`, `goal_range` |
| 8 профилей с разными цветами + новый | цвет по кругу |
| удалить единственный | отказ |
| удалить активный из двух | активным стал оставшийся |
| сохранить, закрыть и открыть БД | профили и активный на месте |

## Ключ к корректности / риски
Активный профиль и список должны быть согласованы всегда: удаление активного, удаление в момент без активного, первый запуск. Миграции БД — только вперёд и только в `src/db`, иначе следующий выпуск потеряет данные ученика.

## Итог реализации
**Сделано.** `app/src/db` — локальная БД на IndexedDB (схема/миграции вперёд, `transact`, `navigator.storage.persist()`), решение `D-16`. `app/src/features/profiles`: модель и валидация черновика, выбор цвета, порт `ProfileRepository` + адаптер на IndexedDB (удаление и смена активного — одной транзакцией), Pinia-стор (`ready` — однократная загрузка, `create/update/remove/switchTo/setInterfaceLocale`, язык интерфейса следует за активным профилем), guard первого запуска `profileRedirect`, `ProfileForm`, `ProfileAvatar`, `useProfileEditor`. **Проверка.** typecheck, lint, 142 теста (профили — 37: домен, стор на репозитории в памяти, guard, integration на fake-indexeddb с «перезапуском» БД), сборка.
