## Контекст / зачем
Методика (brief): слова идут по частоте с разбивкой по частям речи («глаголы: 37/500»), у слова 2–3 примера на темах «путешествия» и «IT», формы и спряжения, пара во втором языке (мост EN↔ES), род у испанских существительных, правило чтения в карточке. Контент наполняется на этапе BL-3 из частотных списков — формат должен быть удобен и для ручного, и для генерируемого заполнения.

## Цель
Контракт словаря v1: спецификация, JSON Schema для редактора, валидатор с понятными ошибками на языке интерфейса (как у текстов), небольшой пример EN и ES в `content/dictionary/`, проверяемый в `npm run test`.

## Объём
**Входит:**
- спецификация `.flow/dictionary-format.md`: файл, статья, формы по языку × части речи, примеры, пара, правила проверки;
- общий модуль проверки контента `features/content` (путь, проблемы, базовые проверки) — валидатор текстов переходит на него без изменения поведения; сообщения — пространство `content.issue.*`;
- валидатор файла словаря и набора файлов (перекрёстные правила: уникальность id и ранга, пары);
- JSON Schema + сверка с валидатором на примерах;
- пример: 5 частотных глаголов ES и EN с парами, существительные ES с родом.

**Не входит:**
- наполнение топ-списков (BL-3, после спайка источников и лицензий);
- загрузка словаря в приложение, экран «Словарь», карточка слова (BL-3);
- генерация правильных форм (спряжение по правилам) — формы, которых нет в файле, приложение не выдумывает.

## Критерии приёмки (AC-1…N)
- **AC-1.** Пример словаря из `content/dictionary/` проходит проверку без ошибок; файлы проверяются в `npm run test`.
- **AC-2.** Каждое правило-ошибка спецификации даёт ошибку с путём и сообщением на RU/EN/ES; предупреждения не блокируют.
- **AC-3.** Повтор id слова или ранга в части речи (в т. ч. между файлами одного языка), неразрешимая пара — находятся.
- **AC-4.** Валидатор текстов после выноса общего модуля ведёт себя как раньше (его тесты не менялись по смыслу).

## Решения
- **D-1. id статьи — ключ прогресса слова** (`word:<lang>:<id>`): стабильный, строчные буквы любого алфавита, цифры, дефис — `año`, `tener`, `banco-2` (омонимы — суффиксом). Транслитерация запрещена: `año` ≠ `ano`.
- **D-2. Файл = язык + произвольный срез** (обычно часть речи: `es.verbs.json`); статьи языка собираются из всех файлов, проверки уникальности — по набору.
- **D-3. Ранг — частота внутри части речи** (1 — самое частое): «глаголы: 37/500» считается по нему.
- **D-4. Формы — закрытый набор ключей на язык × часть речи**; ES-времена — массив из 6 лиц (yo, tú, él/usted, nosotros, vosotros, ellos/ustedes). Неправильный глагол EN обязан иметь past и participle.
- **D-5. Род обязателен у существительного ES** (`m`, `f`, `mf`) — без него слово учится с ошибкой в артикле.
- **D-6. Пара — ссылка `<lang>:<id>` на статью другого изучаемого языка**; неразрешённая в наборе — предупреждение (второй язык могут ещё не наполнить).
- **D-7. Тема примера — из закрытого списка** (`travel`, `it`, `daily`); новые темы (BL-12) добавляются в формат без смены версии.
- **D-8. Лицензия файла обязательна** (`own`, `public-domain`, `cc0`, `cc-by`, `cc-by-sa`) + `source` для атрибуции — частотные списки приходят из внешних источников (спайк BL-3).

## Подход
Спека → вынос `features/content/check.ts` (класс базовых проверок) из валидатора текстов, прогон его тестов → типы и валидатор словаря (файл + набор) тестами-вперёд → схема + пример + `content.spec` → сообщения i18n.

## Тесты
Класс риска: **К2** (валидация), **К1** — уникальность id (ключ прогресса). Таблица «вход → ожидание» — в `dictionary/domain/validate.spec.ts` по правилам спецификации; сверка со схемой — на примерах и негативных фикстурах.

## Ключ к корректности / риски
id статьи — ключ прогресса: правило id нельзя будет ослабить или поменять без миграции прогресса, а дубли между файлами одного языка смешали бы прогресс двух слов. Вынос общего модуля не должен изменить ни одного сообщения валидатора текстов.

## Итог реализации
**Сделано.** Спецификация `.flow/dictionary-format.md` (D-19). Общий модуль `features/content`: коды проблем, разбор JSON, базовый класс проверок `Checker`, сообщения — пространство `content.issue.*`; валидатор текстов переведён на него. `features/dictionary`: типы, закрытый набор форм на язык × часть речи, валидатор файла (структура, id — ключ прогресса, ранг, род ES, формы и лица, переводы, пара, лицензия/атрибуция, предупреждения про примеры и русский перевод) и набора файлов (повтор id/ранга между файлами языка, пары). JSON Schema `content/schema/dictionary.schema.json`. Пример: `content/dictionary/es.verbs.json` (ser, estar, tener, hacer, ir, poder со спряжениями), `es.nouns.json` (с родом, в т. ч. `año`, `mf`), `en.verbs.json` (be, have, do, go, can) — пары EN↔ES разрешаются.

**Проверка.** typecheck, lint, 247 тестов; покрытие К1/К2 — 92,1 %. Валидатор текстов после выноса общего модуля — те же тесты зелёные без изменений по смыслу (AC-4). Мутационная проверка: отключённые «род обязателен» и «повтор id между файлами» ловятся. Сверка схемы и валидатора — на примерах и 9 негативных фикстурах.

**Отклонения.** Из спецификации убрано правило «файл больше 1 МБ»: словари генерируются, размер — не признак ошибки. Добавлена часть речи `phrase` (устойчивые выражения: hay que, be going to). Модальный `can` описан без `irregular` (нет причастия) — с пояснением в `note`.

**Грабли.** Prettier переносит `// eslint-disable-line` на следующую строку — в спеках выносить тип в алиас с `eslint-disable-next-line`.

**Долг.** Нет. Ранги в примере условные — заменятся при наполнении (BL-3).

**Проверка AC:** AC-1 — content.spec словаря: 3 файла без ошибок и предупреждений · AC-2 — validate.spec: правила 2–9, сообщения в content.issue.* RU/EN/ES (issue-message.spec) · AC-3 — validate.spec набора: повтор id/ранга между файлами, pair_not_found · AC-4 — texts validate.spec и content.spec зелёные после выноса Checker
