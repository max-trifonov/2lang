# LNG-S1-003 — Загрузка JSON-текста в приложение: проверка, ошибки, обновление по id

| Поле | Значение |
|---|---|
| Статус | `[x]` |
| Уровень | M |
| Эпик | BL-2 |
| Приоритет | высокий — без загрузки свои песни (`D-3`) в приложение не попадают |
| Связи | `D-3`, `D-5`, `D-6`, `D-16`; `.flow/content-format.md` «Обновление и прогресс» |
| Зависит от | LNG-S1-001 (валидатор), LNG-S1-002 (БД, профили) |
| Блокирует | BL-6 (библиотека, чтение, фразы в повторение) |
| Артефакты | `app/src/features/texts/`, `app/src/db/`, `app/src/pages/texts/` |

## Контекст / зачем
Автор (`D-3`) пишет песню в JSON на компьютере и загружает её на телефон. Если файл с ошибкой — должно быть видно, где и что исправить, а не «не удалось». Исправленный файл с тем же `id` заменяет старый, и уже выученные фразы не теряются.

## Цель
Вкладка «Тексты» с кнопкой «Загрузить»: файл проверяется, корректный сохраняется на устройстве, при совпадении `id` — замена после подтверждения с итогом по фразам; ошибки и предупреждения показываются списком с местом и сообщением на языке интерфейса.

## Объём
**Входит:**
- хранилище текстов в БД (миграция v2: стор `texts`), тексты общие для всех профилей устройства;
- план загрузки (чистая функция): «невалиден» / «новый» / «замена» (итог по фразам: остались, добавились, ушли) / «без изменений»;
- выбор одного или нескольких файлов, результат по каждому файлу: загружен, загружен с предупреждениями, не загружен (список проблем с путём и сообщением);
- подтверждение замены текста с тем же `id`;
- вкладка «Тексты»: простой список загруженного (название, язык, тип) — точка входа загрузки и место, где виден результат;
- строки — RU/EN/ES.

**Не входит:**
- фильтры, поиск, удаление, экран чтения, стартовый набор (BL-6);
- прогресс фраз (BL-5) — здесь только гарантия ключа: замена не меняет `phraseKey` неизменных фраз;
- загрузка по ссылке / из облака.

## Критерии приёмки (AC-1…N)
- **AC-1.** Корректный файл после загрузки появляется в списке «Тексты» и остаётся после перезапуска.
- **AC-2.** Файл с ошибками не загружается; для него показан список проблем: место (`stanzas[0].lines[1].phrases[0]`) и понятное сообщение с цитатой, на языке интерфейса. Битый JSON — строка и столбец.
- **AC-3.** Файл с предупреждениями загружается, предупреждения показаны.
- **AC-4.** Файл с уже загруженным `id` заменяет текст только после подтверждения; в подтверждении — сколько фраз остаётся, добавится и уйдёт. Отказ оставляет старый текст. Файл без изменений — «уже загружен, без изменений».
- **AC-5.** Можно выбрать несколько файлов сразу — итог по каждому.
- **AC-6.** Тексты общие для всех профилей устройства.

## Решения
- **D-1. Библиотека текстов — общая для устройства**, не на профиль: автор загружает песню один раз для семьи; прогресс по фразам будет свой у каждого профиля (BL-5). У записи — кто и когда загрузил.
- **D-2. Итог замены считается по `phraseKey`** — тем же ключом, к которому привяжется прогресс: «осталось» = прогресс сохранится.
- **D-3. Предел размера файла — 1 МБ**: песня — единицы КБ; больше — почти наверняка не тот файл, и разбирать его на телефоне незачем.
- **D-4. Первая миграция схемы БД (v1 → v2)** — с тестом на сохранность профилей при обновлении: данные учеников в установленных PWA уже есть.

## Подход
`texts/domain/import-plan.ts` (`planImport`, `phraseKeys`) → `texts/storage.ts` (порт + IndexedDB) → миграция v2 в `src/db` → стор `useTextsStore` (`ready`, `importFiles` → результаты, `confirmReplace`) → `pages/texts/TextsPage.vue` (список, загрузка, шторка с результатами) + вкладка.

## Тесты
Класс риска: **К2** — план загрузки (ветки, итог по фразам), стор; **К1** — миграция v1→v2 (данные учеников сохраняются), хранилище текстов. UI — К3: ручной смоук по AC.

| Вход | Ожидание |
|---|---|
| валидный, `id` новый | `new` |
| невалидный / битый JSON / > 1 МБ | `invalid` с проблемами |
| тот же `id`, перевод правлен, одна фраза добавлена, одна изменена | `replace`: kept/added/removed посчитаны по ключу |
| тот же `id`, тот же текст (другое форматирование JSON) | `unchanged` |
| БД v1 с профилем → открыть v2 | профиль на месте, стор `texts` есть |
| 3 файла: ок, ошибка, замена | три результата, замена ждёт подтверждения |

## Ключ к корректности / риски
Миграция схемы не должна трогать существующие сторы — у семьи уже есть профили. Замена — только после явного «да»: «обновление по id» без подтверждения молча перетрёт чужую песню с тем же id.

## Итог реализации
**Сделано.** Миграция БД v2 (стор `texts`) с тестом сохранности профилей при обновлении. `features/texts`: `planImport` (invalid / new / replace с итогом по фразам через `phraseKey` / unchanged — сравнение канонического JSON), `tooLargePlan` (> 1 МБ файл не читается), хранилище библиотеки (общей для устройства, `D-17`), стор `useTextsStore` (`ready`, `importFiles` по очереди, подтверждение замены — колбэком от страницы), `ImportResults` (итог по файлу: статус, ошибки и замечания с путём и сообщением). Вкладка «Тексты» (`pages/texts/TextsPage.vue`): загрузка одного или нескольких файлов, подтверждение замены, список, состояния загрузка / пусто / ошибка.

**Проверка.** typecheck, lint, 157 тестов, сборка; покрытие К1/К2 `features` + `db` — 91,7 %. Ручной смоук headless Chrome по AC-1…AC-6: пачка из 4 файлов (загружен, ошибки с путём и цитатой, битый JSON со строкой:столбцом, замечание), перезапуск, повторный файл «без изменений», замена — отказ и согласие с итогом «останется 4, добавится 1, уйдёт 0», второй профиль видит те же тексты.

**Отклонения.** Исправлены типы формата из LNG-S1-001: `Localized & { phrases: Phrase[] }` нельзя было построить литералом (индексная сигнатура `string`) — теперь сигнатура с объединением и `textIn(node, lang)` для чтения оригинала/перевода.

**Грабли.** Фоновая команда с `cd …/app && npx vite` стартовала в корне 2Lang и скачала чужой vite — dev-сервер запускать через `npm --prefix app run dev`.
