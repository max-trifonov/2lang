# LNG-S1-006 — Экспорт и импорт профиля в файл (резервная копия)

| Поле | Значение |
|---|---|
| Статус | `[x]` |
| Уровень | M |
| Эпик | BL-1 |
| Приоритет | высокий — единственная страховка данных до синхронизации (`D-10`) |
| Связи | `D-10`, `D-16`, `D-17` |
| Зависит от | LNG-S1-002 |
| Блокирует | — (каждый будущий стор ученика подключается к копии) |
| Артефакты | `app/src/features/profiles/backup/`, `app/src/db/` |

## Контекст / зачем
Всё хранится только на телефоне (`D-10`). Сломался, потерялся, сменил телефон, очистил данные браузера — прогресс пропал. До синхронизации (этап 2) страховка — файл, который человек сохраняет себе (в «Файлы», облако, мессенджер) и из которого восстанавливается на любом устройстве.

## Цель
Из профиля — «Сохранить в файл»; на новом устройстве (в том числе с экрана первого запуска) и на старом — «Восстановить из файла». Формат резервной копии версионирован и расширяется будущими данными ученика.

## Объём
**Входит:**
- формат `2lang/backup` v1: профиль + раздел данных ученика (по сторам, сейчас пуст) + дата и версия приложения;
- экспорт активного профиля: поделиться файлом (Web Share API — «Файлы», облако, мессенджер) или скачать;
- импорт: проверка файла с понятной ошибкой; профиль с тем же `id` заменяется только после подтверждения; новый — добавляется (имя занято другим профилем — к имени добавляется номер) и становится активным;
- «Восстановить из файла» на экране первого запуска;
- договорённость в `src/db`: стор с данными ученика попадает в копию и удаляется вместе с профилем.

**Не входит:**
- тексты библиотеки (`D-17`: общие для устройства, исходные файлы — у автора) — в копию не входят;
- автоматическое/периодическое копирование, напоминание о копии;
- нативное сохранение через Capacitor Filesystem (сборки — этап 3, BL-13).

## Критерии приёмки (AC-1…N)
- **AC-1.** «Сохранить в файл» в профиле отдаёт файл `2lang-<имя>-<дата>.json` (поделиться или скачать).
- **AC-2.** На устройстве без этого профиля импорт файла восстанавливает профиль (настройки и данные) и делает его активным; с экрана первого запуска — тоже.
- **AC-3.** Импорт профиля, который уже есть на устройстве, заменяет его только после подтверждения; другие профили не меняются.
- **AC-4.** Чужой, битый или более новой версии файл — понятная ошибка, на устройстве ничего не меняется.
- **AC-5.** Имя восстановленного профиля занято другим профилем — профиль восстанавливается как «Имя 2».

## Решения
- **D-1. Единица копии — профиль**, а не всё устройство: в семье каждый сохраняет своё; восстановление одного не трогает других.
- **D-2. Тексты не входят** (`D-17`): общие, исходные файлы у автора; прогресс по фразам без текста безвреден и оживает, когда текст загрузят снова.
- **D-3. `id` профиля сохраняется** при восстановлении: повторный импорт того же человека — замена, а не дубль.
- **D-4. Поделиться (Web Share API) — первым**, скачивание — запасной путь: на телефоне `download` у ссылки в установленной PWA ненадёжен, «Поделиться» сразу даёт «Сохранить в Файлы».
- **D-5. Версия формата > известной — отказ**, а не попытка: файл из будущей версии приложения может нести данные, которые старая версия молча потеряет.

## Подход
`profiles/backup/format.ts` (`buildBackup`, `parseBackup` → профиль + данные | ошибка) → `profiles/storage.ts` `restore(profile, data)` одной транзакцией → стор `importBackup` (план: new / replace / ошибка, имя с номером) → UI: кнопки в «Профиле» и на `welcome`, подтверждение замены, `shareOrDownload` в `shared/native`.

## Тесты
Класс риска: **К1** — целостность данных ученика: разбор и проверка файла, round-trip «экспорт → импорт» (property-based), транзакция восстановления на IndexedDB. UI — К3, ручной смоук.

| Вход | Ожидание |
|---|---|
| экспорт → импорт на пустом устройстве | профиль тот же (id, настройки), активный |
| случайный профиль (fast-check) | `parseBackup(serialize(build(p)))` ≡ p |
| не JSON, чужой `format`, `version: 2`, профиль с пустым именем, лишний стор | ошибка с кодом, данных нет |
| тот же id есть | план `replace`; отказ — без изменений |
| имя «Анна» занято другим id | «Анна 2» (а если и оно — «Анна 3») |

## Ключ к корректности / риски
Импорт не должен частично применяться: профиль и его данные пишутся одной транзакцией, проверка — до записи. Файл — внешний ввод: всё, что из него берётся, проходит ту же валидацию, что и форма профиля.

## Итог реализации

Хранилище профилей: `exportData`, `restore` (профиль, активный и данные — одной транзакцией; удаление старых записей строго до записи новых), каскадное удаление данных в `remove`. Стор: `exportActive`, `planRestore`, `applyRestore`. `shared/native/files.ts` `saveFile` — Web Share API, иначе скачивание (перенесено в шаблон, `D-19` шаблона). UI: «Резервная копия» в профиле, «Восстановить из файла» на экране первого запуска, подтверждение замены с датой копии.
